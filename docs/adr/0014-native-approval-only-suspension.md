# ADR-0014：挂起只走引擎原生审批，删除 `replay-signal`

- 状态：Accepted（Amends [ADR-0012](0012-reliability-by-interception.md)）
- 日期：2026-09-05

## 背景

Agent 跑到一半需要人工审批时，得让它停下来。ADR-0012 设计了两条路径：

- **`native-approval`**：引擎自己支持两段式审批（先返回审批请求并结束本轮，批完再调一次接着跑）。
- **`replay-signal`**：引擎不支持时的兜底 —— 在受管工具入口**抛异常**炸开引擎的调用栈强行中断，
  恢复时把整个循环重跑一遍，跑到同一个工具时从审批存储直接返回结果。

## 决策

**删除 `replay-signal`。** `EngineCapabilities.suspend` 收敛为 `'native-approval' | 'none'`。
`none` 的引擎不支持 HITL：spec 里若声明 `approval`，**启动时**拒绝。
`SuspendSignal` 及其栈解开语义从 `@ca/core` 移除。

## 理由

1. **机制本身不可控**。在别人的代码里抛异常，由别人的 `try/catch` 决定怎么接 —— 引擎完全可能
   吞掉它、把它当成工具失败塞回给模型、或在 `finally` 里做我们不期望的清理。
   这是整个设计里最脆的一环。
2. **实测覆盖率不需要它**。AI SDK 的 harness 适配器能力表显示，9 个适配器中 **8 个有内建 tool approval**，
   唯一没有的是 **Codex**。为 1/9 的场景保留最脆的机制不划算。
3. **失败模式更好**。`none` 让不支持 HITL 的引擎在**启动时**就报错，
   而不是跑到一半才发现停不下来 —— 后者会在生产里表现为"审批工具直接执行了"，是最坏的一类故障。
4. **core 变简单**：不再需要"重放到同一工具调用再返回结果"这条特殊路径。

## 代价

- Codex 类引擎无法做人工审批。→ 显式拒绝而非静默降级；需要 HITL 时换 `ai-sdk/tool-loop`
  或其他 8 个有原生审批的 harness。
- 将来若出现大量无原生审批的引擎，此决策需重新评估。届时正确的做法是**推动上游支持**，
  而不是恢复 `replay-signal`。
